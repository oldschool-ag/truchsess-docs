An [agent](/start/glossary/#agent) is the helper that does the work. It comes in a package: a signed file that ends in `.truchsess-bundle.tar`. Everyone sees the agents on the page **Agents**, and each person has their own agents there. The administrator also adds agents from the **Store** there. Files, the store connection, each install in detail and the trusted publishers are in **Settings** › **Advanced** › **Agents**. The rules for every agent are in **Settings** › **Advanced** › **Agent rules**. **Advanced** is the link **Advanced (for experts)** at the bottom of **Settings**.

**Settings** › **Advanced** › **Agents**, from top to bottom: **Update or install from files**, **Store connection**, **Installed agents in detail**, **One file in detail**, **Trusted publishers**.

**Settings** › **Advanced** › **Agent rules**, from top to bottom: **Owner policy**, **Which AI providers may see your data**, **Autonomy levels**, **Agents may work on a schedule**, **Grant a standing approval**, **Standing approvals**. The panel **Autonomy levels** is explained on [Autonomy levels](/admin/autonomy-levels/). The data rule is explained on [AI providers and lanes](/admin/ai-providers-and-lanes/).

How the store checks publishers and packages before they reach you: [Trust](https://faivr.ai/docs/trust) in the store's documentation.

## Who can do this

- **The administrator** installs, updates, changes and removes agents, adds copies, decides who may use an agent and what it may do, and allows work on a schedule. Trusting a publisher works only in the office, on the local address.
- **Everyone** has their own agents: adds an agent with its card's button (a member asks an administrator first), removes it from their own agents, asks to allow a permission, and switches an agent's routines on for themselves.

## What you need

- For a store agent: the box is connected to the store and the function is subscribed. See [Store](/admin/store/).
- For a signed file: the file ends in `.truchsess-bundle.tar` and its publisher is trusted on the box (see [Trusted publishers](#trusted-publishers)).

## Your agents

Each person has their own agents. A person gives tasks only to the agents in their own row **Your agents**, and the box itself checks this before every task: a task for an agent that is not in the person's agents does not start. The person reads "... is not in your agents. Add it on the Agents page; an administrator may need to allow it first." An administrator may use every agent and adds any agent at once.

The page **Agents** shows cards in two rows:

- **Your agents**: the agents you may use. Truchsess, the agent that comes with the box, is always first.
- **More agents on this box**: the other agents on the box. Each card has **Add this agent** (or **Add these agents** for a function with several agents).

An agent you install from the store or from a file goes into your own **Your agents**. The other people add it themselves, or you add them under **Who may use it** on its card.

### Add an agent to your agents

1. Open **Agents**.
2. Under **More agents on this box**, press **Add this agent** on the agent's card.

An administrator gets it at once: "Added. ... is in your agents." For a member, the button asks an administrator: "You see the answer here and on Home." The card then shows whom you asked and at what time. The administrator answers on **Home**, section **Needs you** ("... asks to use ..."), with **Allow** or **Not now**. The member sees the answer on the card and on **Home**: "... allowed .... It is in your agents now." or "... did not allow ... for now." A member can ask once a day per agent.

Adding an agent costs the person nothing. The company pays for its agents.

### Open an agent's settings

Click a card to open the agent's settings: a panel beside the page, or the whole screen on a phone. Everyone sees:

- **Start a chat**;
- **Recent tasks**: your last five tasks with this agent;
- "What ... may do": every permission the agent asks for, in plain words, with its state (see [What an agent may do](#what-an-agent-may-do));
- **Works on its own**, when the agent offers work on a schedule (see [Agents that work on a schedule](#agents-that-work-on-a-schedule));
- "Your connections ... uses", when the agent uses one of your connections;
- **How it works with you**: what the agent learned from you;
- **Remove from my agents**, which takes it off your own row. You can add it again under **More agents on this box**. An agent that is open to everyone stays in your agents.

An administrator also sees the part **For administrators**:

- **Who may use it**: choose **Everyone** or **These people**. **Everyone** also covers people you add later: "Every person on this box may use ..., also people you add later." With **These people**, the list shows each person with **Remove**; choose a person and press **Add** to add one. Truchsess is always for everyone: "Truchsess is for everyone on this box".
- **Allowed without asking**: the agent's standing approvals, read only. They are changed in **Settings** › **Advanced** › **Agent rules**.
- **Its install answers**: what you answered at install.
- **Another copy** with **Add another copy**, when the store sells copies of the agent (see [Add another copy](#add-another-copy)).
- **Remove from this box**, then **Confirm remove**: "Every binding is reversed and its workspace is removed; nobody can use it after that." For a store function, all of its agents are removed together. A paid copy beyond the first has **Stop this copy** instead (see [Add another copy](#add-another-copy)).

On the page **Agents** an administrator also has the button **Store**. See [Store](/admin/store/).

### What a card shows

- The agent's name and one line under it: the store function it belongs to. An agent installed from a file shows the store function its package belongs to, or the package's own title.
- The agent's face: the picture of its store function, however the agent was installed. The box refreshes the store's list and its pictures once a day by itself; a picture that could not be loaded is fetched again the next day. Until then the card shows the agent's first letter.
- An agent installed from a file says so on its card and at the top of its settings: "Installed from a file, not from the store: no updates from the store."
- A tag with its state, for example "Idle", or "Working on: ..." with what was asked while it works.
- Its last line: when it last finished a task and what was asked, for example "Last task finished 13 Oct: Check example-bakery.ch". It never shows the agent's own answer. Open the task or **Home** › **Recent results** for that.
- When your own last task with it failed: "Problem:" and the reason, with **Open the task** and **Ask Truchsess why**. A card shows only your own tasks, for administrators too; a colleague's failed task is not on your card. An agent you have not used yet has no tag.
- For administrators: the agent's cost this month, "This month" and the amount in your budget's currency, or "No cost recorded". It is the same amount as in **Settings** › **Advanced** › **AI**, panel **Costs in detail**.
- For administrators: what the agent needs from you, at most one line, for example a repository it cannot reach, with the buttons that fix it. The fix applies to every agent of the function that needs it.

### What an agent may do

"What ... may do" in the agent's settings is the one place for what this agent may do. Each line has one state:

| State | Meaning |
| --- | --- |
| "Allowed" | Your company rules allow it. |
| "Allowed for this agent only" | An administrator allowed it for this agent alone. |
| "Not allowed by your company rules" | The owner policy does not allow it. |
| "Declined at install" | It was declined when the agent was installed, for example a skipped question. |
| "Needs a connection" | It needs a connection first, for example your mailbox. |

- **Administrator:** press **Allow for** and the agent's name on a line, then confirm. Only this agent gets it, at once. A protected permission (publishing, sending messages, spending, passwords and keys, deploying) asks you to tick a second line first: "I understand this and allow it for ... only." **Remove** takes it back: "The company rules apply to ... again."
- **Member:** press **Ask to allow** on a line. The administrator decides on **Home**, section **Needs you**. You see the answer on the line and on **Home**.

All hand-offs of one agent are one line, with **Allow all hand-offs for** and the agent's name. **Details** shows each agent it can hand work to, each with its own **Allow**. An agent that is not installed here is marked "(not installed)".

### Functions with several agents

Some store functions have several agents that work together, for example Bob for software delivery. They are one card. You add, remove and allow them together, as the store sells them as one.

A function with a lead answers as one agent. You talk to the lead, for example Bob, and Bob decides which of his roles takes the task, and can hand it to several in turn. In **Chat** the function is one entry. The run shows the chain, for example "Bob → QA Reviewer → Merge Gate", what each role did and what it cost, and the total. A role that would change a repository still waits for your approval.

The function's settings list its agents by role, each with its own "What ... may do". Only the lead has **Start a chat**. An administrator has **Test this role alone** on each other role: it opens **Chat** with that one role, for testing. A member who sends a task to one role reads "Ask ... decides which role takes the task and hands it on." and nothing starts.

A function has one lead. Installing a second lead is refused with a sentence that names the first one, "... already has a lead: ...", and says to remove that lead from this box first.

**Settings** › **Advanced** › **AI**, panel **Costs in detail**, part **Per agent this period**, lists the function's tasks one line each, with the chain and its cost.

### Installed agents in detail

**Settings** › **Advanced** › **Agents**, panel **Installed agents in detail**, lists every install on the box with what you can do with it. There is one card per function you subscribed to and one card per package installed from a file, marked "Installed from a file".

A function's card shows its name, its monthly price, a badge with the subscription state and a line in words, for example "Subscribed, not installed yet". It also holds **Cancel subscription** and **Manage subscription**. See [Store](/admin/store/#manage-a-subscription).

Inside the card, each agent of the function is listed with each of its installs. One install shows:

- its name, and the product it works for, if any;
- its state in words, for example "Running";
- "Ready", or "Needs ... from the admin" with **Open Connections**, while it is a working install. See [Connections](/admin/connections/#what-ready-means);
- its lane, for example "Standard lane";
- how many permissions it was granted;
- your install answers, one per line;
- "What ... may do": each permission with its state. **Allow for** and the agent's name allows one line for this agent only;
- only the buttons its state allows (see the table below);
- **Details**: **Version**, **Model**, **Came from**, **State on record**, the lists "Granted:" and "Declined:", and under **Technical details** the **Package id**, **Install id**, **Agent id** and **Sandbox**.

The page fits a screen from 360 px wide. Nothing scrolls sideways.

## Trusted publishers

New to Agent rules? Read [Agent rules explained](/admin/agent-rules/) first: what decides what an agent may do, in plain words, with examples.

An agent is installed only when its package is signed by a publisher in this list. When the list is empty, it says "No publisher is trusted yet. Every install fails closed until one is registered."

For the store's own publisher you need no key: press **Allow agents from** and the publisher's name above the cards in **Agents** › **Store**. See [Store](/admin/store/#the-publisher-is-not-trusted-here-yet).

For another publisher:

1. Open **Settings** › **Advanced** › **Agents**, panel **Trusted publishers**.
2. Paste the key under **Public key (PEM, from the .pub file)**, or choose the file under **Or upload the .pub file**.
3. Enter a **Label**, for example the publisher's name.
4. Press **Add publisher**.

**Remove**, then **Confirm remove**, takes a publisher off the list: "Agents signed with it can no longer be installed or updated; installed agents keep running."

## Owner policy

How the owner policy combines with install answers, levels and the data rule: [Agent rules explained](/admin/agent-rules/).

The owner policy is the list of permissions any agent may receive. An agent receives exactly the permissions it asks for that are also on this list, plus what your install answers allow. Everything else is declined at install. A new box starts with a recommended policy: an agent's own files and tools, reading the websites a person names in a task, the person's mail (read and draft), calendars, Home, the company memory, the company task list, the cheap and standard levels of AI, and publishing and sending messages (each still asks first).

1. Open **Settings** › **Advanced** › **Agent rules**, panel **Owner policy**.
2. Read the families: **Workspace**, **Commands**, **Internet**, **Repositories**, **Knowledge**, **Workboard**, **Delegation**, **Protected actions**, **Model lane**, **Browser**, **Company mail**, **Calendars**, **Home**, **Company memory**.
3. Tick a permission to allow it. For a permission with a value (a host, a repository, a product, an amount, a level of AI), enter or choose the value and press **Allow**. Press **×** on a value to remove it.
4. Press **Save policy**. Next to the button you see "Saved ..." with the time, or "Not saved: ..." with the reason.

To allow a permission for one agent only, open the agent's line under "What ... may do" and press **Allow for** and the agent's name. The owner policy then says "Also allowed for:" and the agent.

The words the portal shows, for example:

| Permission | In plain words |
| --- | --- |
| Workspace | "Read its own files", "Create and change its own files" |
| Commands | "Use its own tools, closed off from the rest of the box" (never on the box itself) |
| Internet | "Reach the internet addresses your company allows", "Reach one named host", "Read the websites a person names in a task (only those, only for that task)" |
| Repositories | "Read one repository", "Push its own branches and open pull requests on one repository, never merges (includes read)", "Read test results and logs in one repository", "Comment on and review pull requests in one repository", "Create and update issues in one repository" |
| Knowledge | "Read one product's knowledge", "Write one product's knowledge" |
| Workboard | "Read the company task list", "Change the company task list" |
| Delegation | "Hand work to one other installed agent" |
| Protected actions | "Publish content outside (asks first)", "Send a message to a person or an external system (asks first)", "Spend money up to a per-action limit (asks first)", "Read or use a stored password or key (asks first)", "Deploy or release (asks first)", "Submit an on-chain transaction (asks first)" |
| Model lane | "Use one level of AI (cheap, standard or the strongest)" |
| Browser | "Open web pages and take screenshots with its own browser (needs its own tools and the allowed addresses)" |
| Company mail | "Read the company mailbox of the person who gives the task", "Write drafts in the company mailbox of the person who gives the task (never sends)" |
| Calendars | "Read the calendars of the person who gives the task (never changes them)" |
| Home | "Put items on Home for the person it works for (tasks, meetings, drafts, reports)" |
| Company memory | "Search the company memory (company, its products, its own and the person's records)", "Propose what the company memory keeps (a person or the administrator decides what guides later work)" |

A repository, product or website chosen as an install answer is allowed by that answer. You do not have to list it in the owner policy.

A saved owner policy applies to the next install, update or **Change**. Agents that are already installed keep their permissions until then. When your rules now allow something an install was installed without, its row in **Installed agents in detail** says so and offers **Apply the rules**.

## Install questions

Some agents ask questions at install, under "This agent asks you to choose:".

| Kind | What you choose | Notes |
| --- | --- | --- |
| Repository | One repository from your GitHub connection. | If GitHub is not connected, the box says so and offers **Open Connections**. GitHub is in **Settings** › **Advanced** › **Connections**. |
| Product | One of the box's products. | If the list is empty, add a product first in **Settings** › **Advanced** › **Knowledge**, **Add a product**. |
| Website | One website address, for example `www.example.com`. | The agent reaches exactly this host. Wildcards, IP addresses and local names are refused. |

An optional question offers **Skip (the permission is declined)**. The Install button stays greyed out until every required question is answered: "Answer the questions above first."

When you install all agents of a function at once with **Install all**, a question that several of them ask (the same repository or the same product) is asked once. See [Store](/admin/store/#install-all-agents-of-a-function).

## Install from a package file

You can choose many files at once, or look at one file closely first. Both are in **Settings** › **Advanced** › **Agents**.

### Several files at once

1. Open **Settings** › **Advanced** › **Agents**, panel **Update or install from files**.
2. Press **Choose files** and choose the package files, for example everything in one folder.
3. Read the list. Each file is one line: an agent the file updates, with its old and new version; "New agent" with **Install**; or "Already up to date". A file from another publisher, from a publisher the box does not trust, or with a signature that does not match "is not used".
4. For a new agent, press **Install**. The file opens in detail. Go on with step 4 below.

To update the agents the files are newer for, see [Update](#update).

### One file in detail

1. Open **Settings** › **Advanced** › **Agents**, panel **One file in detail**.
2. Choose the **Bundle file** (up to 64 MB).
3. Press **Upload and inspect**.
4. Read the inspection: the agent's name and version, **Version**, **Publisher** ("trusted" or "NOT trusted on this appliance") and **Signature** ("verified"). **Technical details** holds the **Package id**, **Bundle file**, **Publisher key id** and **Package digest**.
5. Read "What it may do:". Each permission is one line with a mark: "granted", "not allowed by your rules" or "you choose at install".
6. Enter the **Name for this install**. The chat shows this name.
7. Answer the install questions.
8. Press **Install**.
9. Follow the steps: "Write the install record", "Verify, unpack and bind the package".
10. If the box asks for a product mapping ("Product mapping needed for ..."), choose an existing product for each name or **Create a new product**, then press **Resume the install**.

The agent then appears in your own **Your agents** on the page **Agents**, and in **Installed agents in detail**, marked "Installed from a file". Set who else may use it on its card, under **Who may use it**.

A store agent is installed from the store instead. See [Store](/admin/store/#install-a-store-agent).

An uploaded file that you did not install is listed under "Uploaded, not installed:". Press **discard** to delete it.

## Install the same package again

A signed package file can be installed several times, for example one agent per website. Upload the file again in **One file in detail**. The inspection says "Already installed as ...". Enter another **Name for this install** and press **Install another**. Each install has its own answers, workspace and memory. All installs of the package are listed on its card in **Installed agents in detail**.

## Add another copy

A second copy of a store agent works on its own: its own name, its own answers (for example another product or another website) and its own work. It costs the same price again. The box offers it only when the store sells copies of the agent's function, and only for a function of one agent. When the store does not, you do not see **Add another copy** at all.

1. Open **Agents** and click the agent's card.
2. Under **For administrators**, part **Another copy**, press **Add another copy**.
3. Check **Its name**. The box proposes one, for example "Product Owner (second product)" or "Gideon (second website)".
4. Answer the agent's install questions, for example which product or which website.
5. Press **Next**.
6. Read the price: "... costs ... per month more." and "Your monthly total becomes ...".
7. Press the button that names the price, for example **Pay CHF 249 per month and add it**. **Not now** leaves without paying.
8. Press **Open the payment page** and pay on the store's payment page.

The box waits ("Waiting for the payment …") and installs the copy as soon as the payment is confirmed: "Added. ... is in your agents." Press **Open** and the copy's name to see its settings. The copy is its own card on **Agents** and **Home**, with its own name.

- If you stop before paying, nothing is installed: "If you stop here, nothing is installed and your answers are kept for the next try." **Add another copy** opens again with your answers.
- A copy you paid for while the page was closed is installed the next time an administrator opens **Agents**.
- **Settings** › **Plan and costs** lists each paid copy as its own line, for example "Product Owner, second copy: CHF 249", and the agents' total per month.

To end a copy, open its card and press **Stop this copy** (the button names the price per month), then confirm. That copy stops working at once, its price ends with the period already paid for, and its finished work stays readable. The first copy is not touched.

A signed package file can be installed several times without the store: see [Install the same package again](#install-the-same-package-again).

## Agents that work on a schedule

Some agents offer work on a schedule, a routine, so the work is ready before people ask. Penn, for example, checks new mail during office hours. A routine runs as one person: the person who switched it on, with their own connections, permissions and budget.

### Allow work on a schedule (administrators)

1. Open **Settings** › **Advanced** › **Agent rules**, panel **Agents may work on a schedule**.
2. Choose **Off**, **On, at most every 15 minutes**, **On, at most hourly** or **On, at most daily**.
3. Press **Save**.

You see "Saved. People can switch routines on in their agents' settings." or, with **Off**, "Saved. No agent works on a schedule." A new box starts with **On, at most every 15 minutes**. A box that was set up with an older version starts with **Off**.

### Switch a routine on for yourself

1. Open **Agents** and click the agent's card.
2. Under **Works on its own**, tick the routine. Its line says what it does and when, for example "Check new mail every 15 minutes, Mon to Fri, 07:00 to 19:00".

The line under it says what the last check found, for example "Checked 10:15, no new mail". A check that finds nothing starts no task and costs nothing. Below that, "This month:" shows the cost and the number of checks and runs.

- **Run now** runs it at once.
- **Pause until …** with **Tomorrow**, **Monday** or **A date …**, then **Pause**. **Let it run again** ends the pause.
- **Change the schedule**: how often (never more often than the agent or your company rule allows), the days and the hours, then **Save the schedule**. Times are on the box's clock (**Settings** › **Your company**, **Time zone**).

After 3 failed runs in a row the routine stops itself. Your **Home** then shows one line with **Turn it on again**. Routine runs carry the tag "Routine" in the run history, with their own filter **Routines**.

## Update

### From the agent's card

When a newer version of an agent is ready, its card on **Agents** says "Update available" and the version, with the first line of what is new.

1. Press **Update** on the card.
2. If the new version may do more than before, a window says what: "... may then also:" and each new permission in plain words. Nothing changes until you press **Allow and update**.
3. **Not now** closes the window. The agent keeps its version.

With two or more updates waiting, **Update all** at the top of **Agents** updates every waiting agent one after the other; its window says **Allow and update all**. **Settings** › **Updates** names the agents' updates too. See [Updates](/admin/updates/).

When **Install updates automatically** is on in **Settings** › **Updates**, "Box and agents update at night, between 02:00 and 05:00 your time." See [Updates](/admin/updates/).

A progress line shows each agent. A failed update never stops the others; the agent keeps running on its version: "... could not be updated; it runs version ... as before."

An agent installed from a file whose package the store sells offers **Get updates from the store** on its card, once. Press it, then **Get updates from the store** in the window: "Its answers, what it may do, its files and its history stay."

### From files

1. Open **Settings** › **Advanced** › **Agents**, panel **Update or install from files**.
2. Press **Choose files** and choose the newer files.
3. Press **Update all from these files**.
4. If a new version may do more, the window lists it. Press **Allow and update all**, or **Not now** to keep the versions.

Each line then says "... runs version ..." or why it was not updated.

### One file, with every detail

Upload the newer file of an installed agent in **One file in detail** and press **Upload and inspect**. What you see next depends on whether the new version changes what the agent may do.

#### The same permissions

The new version asks for the same permissions and the same questions. A question that is only worded differently counts as the same.

1. The inspection offers **Update the install to version** and the version, or **Update all ... installs to version** and the version when there are several installs.
2. Press it.

#### Changed permissions

The new version adds or removes a permission, or adds, removes or changes a question. Then the inspection first shows the change, once for all installs:

- The note "Version ... changes what this package may do." and "The install keeps running ... until you press Update and grant."
- **Adds:** each new permission in plain words, followed by what today's owner policy does with it.
- **Removes:** each permission the new version no longer has.
- A row for each new question. Answer it there.
- When questions changed: "The questions of this package changed: an answer already given is kept where the question still exists."

The update button then reads **Update and grant (the install)**, or **Update and grant (all ... installs)**. It stays greyed out until every required new question is answered.

1. Read **Adds** and **Removes**.
2. Answer the new questions, if any.
3. Press **Update and grant**.

Nothing changes until you press the button. Until then every install keeps running on its current version. To leave the update, do not press the button, or press **discard** next to the file under "Uploaded, not installed:".

After the update each install receives what the owner policy allows plus its answers, as at a new install. A permission the owner policy does not allow stays declined. Earlier answers are kept.

If the file changed after you read the change, the box refuses: "The bundle changed since you reviewed it. Open it again and review its permissions."

**Settings** › **Advanced** › **Activity and audit trail**, **Recent activity**, records the confirmed change with the name of the administrator who pressed the button.

### After every update

Each install keeps its name, answers and workspace. If the new version adds a required question that is still open, that install waits: it shows "Waiting for your answers" and **Choose**. A failure in one install does not stop the others.

## Change an install

1. In **Settings** › **Advanced** › **Agents**, panel **Installed agents in detail**, press **Change** on the install.
2. Change the **Name** or the answers.
3. Press **Save and apply**.

"The install keeps its workspace, memory and identity; its grants, website, repository token and product knowledge follow the new answers."

**Levels** on a running install opens **Settings** › **Advanced** › **Agent rules**, where you set its [autonomy levels](/admin/autonomy-levels/).

## Failed install: Retry or Remove

A failed install never stays half installed. It shows "Install failed" and the error.

- **Retry** runs the install again from the stored file.
- **Remove**, then **Confirm remove**, closes it: "Nothing of it is active; what the failed attempt left behind is reverted and its record is closed."

After **Remove** the install leaves the list. For a store install the box also asks the store whether it still holds it. If the store still holds it, **Install** on the store card takes it over. See [Store](/admin/store/#an-install-the-store-still-holds). If the store could not be reached, the install stays in the list with **Check with the store again**. Press it when the box is online.

## Uninstall

To remove an agent for everyone, open its card on **Agents** and press **Remove from this box** (see [Your agents](#your-agents)). To uninstall one install:

1. In **Settings** › **Advanced** › **Agents**, panel **Installed agents in detail**, press **Uninstall** on the install.
2. Press **Confirm uninstall**.

Every binding is reversed and the agent's workspace is removed. The box keeps a signed receipt and shows each checked effect as "verified". For a store agent the receipt goes to the store. See [Store](/admin/store/#what-happens-to-an-installed-agent).

The uninstalled agent then leaves the list. It stays in the history in **Settings** › **Advanced** › **Activity and audit trail**.

### Finish an unfinished uninstall

If an uninstall stopped halfway, the install stays in the list with "Uninstall not finished" and the note "This uninstall did not finish: the agent no longer runs, but its files may still be on the box and no receipt was signed. Finish uninstall completes it."

1. Press **Finish uninstall**.
2. Press **Confirm uninstall**.

## What you see afterwards

Each install in **Installed agents in detail** shows its state in words, and only the buttons that state allows:

| State | Meaning | Buttons |
| --- | --- | --- |
| "Running" | The agent takes tasks. | **Change**, **Levels**, **Uninstall** (and **Apply the rules** when your rules now allow more) |
| "Waiting for your answers" | A required install question is open. | **Choose**, **Change**, **Uninstall** |
| "Waiting for a product mapping" | A product name in the package is not a product of the box yet. | **Map products**, **Change**, **Uninstall** |
| "Being set up" or "Install not finished" | The install is running or was interrupted. | **Uninstall** |
| "Stopped: the subscription ended" | The store subscription ended. It says "Files are kept until you uninstall." Subscribe again to bring it back. See [Store](/admin/store/#what-happens-to-an-installed-agent). | **Uninstall** |
| "Install failed" | The install failed. | **Retry**, **Remove** |
| "Uninstall incomplete" | An uninstall failed partway. | **Uninstall** |
| "Uninstall not finished" | An uninstall stopped before its receipt. | **Finish uninstall** |
| "Removed" | A removed store install the store could not be asked about. | **Check with the store again** |

A working install also shows "Ready", or "Needs ... from the admin" with **Open Connections**. See [Connections](/admin/connections/#what-ready-means).

Uninstalled agents and removed failed installs are not listed. They stay in the history.

## If it does not work

| What you see | What to do |
| --- | --- |
| "... is not in your agents. Add it on the Agents page; an administrator may need to allow it first." | Add the agent under **More agents on this box** with **Add this agent**. A member waits for the administrator's **Allow**. |
| "You asked already. You see the answer here and on Home." | The ask waits for an administrator. You can ask once a day per agent. |
| No **Add another copy** in the agent's settings | The store does not sell copies of this function yet, the agent came from a file, or the function has several agents. See the box below. |
| "Your store account does not allow a second subscription yet. Please contact Truchsess support." | Contact support. Your answers for the copy are kept. |
| "The payment was not finished. Nothing was installed; your answers are kept for the next try." | Press **Add another copy** again when you are ready. |
| "Your administrator has not allowed agents to work on a schedule." | An administrator chooses a setting other than **Off** in **Settings** › **Advanced** › **Agent rules**, panel **Agents may work on a schedule**. |
| "Stopped after 3 failed runs in a row (...). Turn it on again to go on." | Read the reason in the brackets, fix it, then press **Turn it on again**. |
| "Install failed" on an install | See [Failed install: Retry or Remove](#failed-install-retry-or-remove). |

## Your choices

| Choice | What it does | When to pick it | Can you undo it? |
| --- | --- | --- | --- |
| **Add this agent** | Puts an agent into your own **Your agents**. A member asks an administrator first. | You want to give the agent tasks. | Yes: **Remove from my agents**. |
| **Who may use it** | **Everyone**, or **These people**. | When only some people need the agent. | Yes: choose again. |
| **Allow for** (one agent) | Gives one permission to this agent only. | One agent needs more than your company rules allow. | Yes: **Remove** on the line. |
| **Add another copy** | A second copy of a store agent, with its own name and answers, at the same price again. | A second product or a second website. | Yes: **Stop this copy**. |
| **Test this role alone** | Opens **Chat** with one role of a function, for testing. | You want to check one role without its lead. | Not needed. |
| **Agents may work on a schedule** | Allows routines, and how often they may run at most. | Agents should prepare work before people ask. | Yes: choose **Off**. |
| Tick a routine under **Works on its own** | Runs the routine for you on its schedule. | You want the work ready before you ask. | Yes: untick it. |
| **Add publisher** | Trusts a publisher's signature. | Before the first install from that publisher. | Yes: **Remove**. |
| **Save policy** | Sets what agents may receive. | Before installing. | Yes. Installed agents keep their permissions until their next update, **Change**, **Apply the rules** or a new install. |
| **Install** / **Install another** | Installs an agent. | | Yes: **Uninstall** (the workspace is deleted). |
| **Update** / **Update all** | Moves an agent to its new version. A new permission asks first: **Allow and update**. | "Update available" on a card. | No direct way back. Before you allow it, nothing has changed. |
| **Get updates from the store** | A file install gets its updates from the store from now on. | The store sells the agent's package. | No direct way back. |
| **Update and grant** | Moves every install to the new version. Each install receives what the owner policy allows plus its answers. | You read **Adds** and **Removes** and agree with the change. | No direct way back. Before you press it, nothing has changed. |
| **Change** | New answers or a new name. | An agent should work on another repository, product or website. | Yes: **Change** again. |
| **Retry** / **Remove** | Repeats or closes a failed install. | After a failed install. | n/a |
| **Remove from this box** / **Uninstall** / **Finish uninstall** | Removes the agent and its workspace. | The agent is no longer needed, or an uninstall stopped halfway. | No. Install again for a fresh start. |

<NotYet>
You cannot go back to an earlier version of an agent, add a second copy of a store function with several agents (for example Bob) or of an agent whose function the store does not sell as copies, schedule a task of your own, or change the permissions of an installed agent by saving the owner policy alone. Workarounds: to go back, uninstall and install the older signed file (its workspace is lost); for a second copy, ask the publisher for a signed package file and install it from the file; instead of your own schedule, use a routine the agent offers under **Works on its own**, or start the task in **Chat**; to apply a changed owner policy, press **Apply the rules** on the install in **Installed agents in detail**, or press **Change** and save.
</NotYet>
