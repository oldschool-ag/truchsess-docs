**Settings** › **Advanced** › **Agent rules** holds the rules for every agent on your box: "What any agent may do, how much it does on its own, which AI companies may see the data, and when agents may work on their own." Advanced is the link **Advanced (for experts)** at the bottom of **Settings**. The part **Agent rules** has the panels **Owner policy**, **Which AI providers may see your data**, **Autonomy levels**, **Agents may work on a schedule**, **Grant a standing approval** and **Standing approvals**. The AI models are in **Settings** › **Advanced** › **AI**, the trusted publishers in **Settings** › **Advanced** › **Agents**.

This page explains the rules from zero. The pages [Install and manage agents](/admin/packages/), [Autonomy levels](/admin/autonomy-levels/) and [AI providers and lanes](/admin/ai-providers-and-lanes/) have the step-by-step details.

## The one rule to remember

An agent gets only what it **declares** AND what **your rules allow**.

An agent can never get more than it asked for, and never more than you allowed. If either side says no, the answer is no. Everything you do not allow is declined. A new box starts with a recommended owner policy: what an everyday agent needs, and nothing that costs money.

## What decides what an agent may do

The box applies these in order. The first four decide **what** the agent may do at all. The last three decide **how** and **when** it does it.

### 1. What the agent declares

Every agent comes in a signed package that lists its permissions, for example "Read its own files" or "Reach one named host". This list is fixed by the publisher. You see it before you install: under "What it may do:" on the agent's card in **Agents** › **Store**, or when you install from a file in **Settings** › **Advanced** › **Agents**. After the install, each agent's card on **Agents** shows "What ... may do". The agent pages under [Agents in the store](/agents/) list every permission of every store agent.

Before anything else, the box checks who signed the package. It installs only packages signed by a publisher in **Trusted publishers** (**Settings** › **Advanced** › **Agents**). For the store's own publisher, the store shows one button: **Allow agents from** and the publisher's name.

### 2. Your owner policy

The panel **Owner policy** is your allow list: "What any installed agent may be granted. An agent receives exactly the permissions its package declares that are also allowed here; everything else is declined at install." It is grouped in families: **Workspace**, **Commands**, **Internet**, **Repositories**, **Knowledge**, **Workboard**, **Delegation**, **Protected actions**, **Model lane**, **Browser**, **Company mail**, **Calendars**, **Home**, **Company memory**. You tick a permission, or for one with a value (a host, a repository, a product, an amount, a lane) you enter the value and press **Allow**. Then **Save policy**.

The owner policy is the default for every agent. To allow one permission for one agent only, open the agent's card on **Agents** and press **Allow for** and the agent's name on that line of "What ... may do".

The policy applies when an agent is installed, changed or updated. Saving it alone does not change agents that are already installed. When your rules now allow a permission an installed agent was declined, **Settings** › **Advanced** › **Agents**, panel **Installed agents in detail**, says so on that agent and shows the button **Apply the rules**.

### 3. Your answers at install

Some permissions are about one thing you choose: one website, one repository, one product. The agent asks for it at install, under "This agent asks you to choose:". Your answer is your permission for exactly that one thing. You do not need to list it in the owner policy too. One website means one website: the agent reaches that host and no other one from its answers.

The agent's card shows its answers under **Its install answers**. To change an answer: **Settings** › **Advanced** › **Agents**, panel **Installed agents in detail**, **Change** on the agent, then **Save and apply**.

### 4. "Reach the internet" is not the whole internet

**Reach the internet addresses your company allows** lets an agent go out only through the box's internet filter, on a short fixed list of hosts (the AI providers, GitHub and a few software package sites), plus the exact hosts it was given: its website answer and any **Reach one named host** you allowed. Every other address is refused. Without this permission an agent reaches nothing outside the box, not even its own website.

### 5. The agent's autonomy level

Each kind of action has a level, shown in the panel **Autonomy levels**: **Runs on its own**, **Tells you after**, **Waits for your check**, **Asks you first**, **Always asks, with a reason**. Each kind starts at its floor; "you can raise it for one package, never lower it below the floor." Outside actions start high: **Publishes** and **Sends messages outside the box** ask you first; **Uses credentials** and **Deploys** always ask, with a reason. See [Autonomy levels](/admin/autonomy-levels/#the-default-for-each-kind-of-action).

### 6. Standing approvals

A standing approval lets one agent do one protected action without asking, up to a number per calendar month and until a date. It is the only way to make an "Asks you first" action run on its own. You grant it in the panel **Grant a standing approval** on **Agent rules**. The panel **Standing approvals** lists them, each with **Revoke**. Each agent's card shows its own under **Allowed without asking** (read only). "Uses credentials" and "Deploys" can never have one.

### 7. The data rule and the model lanes

The panel **Which AI providers may see your data**: "Every model request of every agent goes only to providers that meet this rule." If no provider for the agent's model meets it, the box refuses the run before any data leaves. The panel **Model lanes** (**Settings** › **Advanced** › **AI**) decides which model each agent uses: each agent has a lane permission (**Cheap**, **Standard** or **Frontier**), and the table says which model each lane is. See [AI providers and lanes](/admin/ai-providers-and-lanes/).

### 8. The budget

The last check, before every task: when the monthly budget reaches its stop level, no new task starts and **Send** is greyed out. You set the limit on **Settings** › **The AI and costs**, **Monthly limit**. See [Budget](/admin/budget/).

## How they combine

- **At install:** declared AND (owner policy OR your install answer) = what the agent receives. The rest is listed as "Declined (declared but not allowed)".
- **At every task:** the budget must allow a new task, and the data rule must allow the agent's model.
- **At every action:** the level decides whether it runs, tells you, waits for your check, or asks first. A standing approval can turn "Asks you first" into "Runs on its own" within its limit.
- **Some things no rule can allow:** no agent can merge on GitHub or push to the default branch, read a stored key or password, or work outside its own closed workspace.

### When an update asks for more

When a new version of an agent asks for a new permission, nothing changes by itself, and it is never installed at night. **Home** › **Needs you** shows "The new version of ... asks for more", with **Review the update**. The agent's card on **Agents** shows "Update available" and the button **Update**.

1. Press **Update** on the agent's card.
2. A small window opens. It lists the new permissions under "... may then also:".
3. Press **Allow and update**. Or press **Not now**: nothing changes, and the agent keeps running on its version.

**Update all** opens the same window for every waiting agent, with **Allow and update all**. When the box updates, it applies the same rule as at install: declared AND allowed. A new permission your owner policy does not allow is declined; you can allow it for that agent alone on its card. See [Update](/admin/packages/#update).

## Three examples

### Example 1: Gideon checks one website

Gideon (function [Visibility in AI search](/agents/visibility-in-ai-search/)) declares: its own workspace, its own tools in its sandbox, **Reach the internet addresses your company allows**, the browser in its sandbox, **Reach one named host** for the website you choose, **Reach one named host** `html.duckduckgo.com` (a web search page), an optional product's knowledge, and the lane **Standard**.

1. In **Owner policy**, tick **Read its own files**, **Create and change its own files**, **Use its own tools, closed off from the rest of the box**, **Reach the internet addresses your company allows** and **Open web pages and take screenshots with its own browser (needs its own tools and the allowed addresses)**. Under **Reach one named host**, enter `html.duckduckgo.com` and press **Allow**. Under **Use one level of AI (cheap, standard or the strongest)**, choose `standard` and press **Allow**. Press **Save policy**.
2. Install Gideon. Answer its website question with your website, for example `www.example.com`.
3. Gideon now **can**: open and screenshot `www.example.com`, search on `html.duckduckgo.com`, write its report in its workspace.
4. Gideon **cannot**: open any other website (not in its answers, not on your list), change your website (it has no repository permission), publish or send anything (it declares no protected action). Ask it only about `www.example.com`: about any other site it currently writes a misleading "unreachable" report (a known issue; see [One website per install](/agents/visibility-in-ai-search/#one-website-per-install)).
5. If you skipped `html.duckduckgo.com` in step 1, it is listed as declined: Gideon installs, but cannot search.

### Example 2: Website Owner works on your repository

Website Owner (function [Website care](/agents/website-care/)) declares **Push its own branches and open pull requests on one repository, never merges (includes read)**, with a question for the repository that holds the website's source, plus its website, its workspace, its tools, the internet, the browser, the workboard and the lane **Standard**.

1. Connect GitHub first: **Settings** › **Advanced** › **Connections**, panel **GitHub**.
2. In **Owner policy**, tick the plain permissions it lists and allow the lane `standard`. You do not list the repository: your answer at install allows it.
3. Install it. Choose the repository and the website.
4. It **can**: read the repository, push its own branches, open pull requests, check them against the live site. Its level for **Pushes its own branches and opens pull requests** is **Tells you after**: you see a "Told you after" line on **Home** › **Recent results**.
5. It **cannot**: merge, push to the default branch, or touch any other repository. A person merges the pull request on GitHub.
6. You want to read each result first: raise **Pushes its own branches and opens pull requests** to **Waits for your check** in **Autonomy levels**. The branch is still pushed; the result waits on **Home** › **Needs you** for your **Accept**.

### Example 3: An update asks for one more permission

You use an agent installed from a package file. The publisher sends version 1.1, which adds **Reach one named host** `api.example.com`.

1. Open **Settings** › **Advanced** › **Agents**, panel **Update or install from files**, and press **Choose files**. Choose the new file.
2. The box shows the agent with its old and new version. Press **Update all from these files**.
3. A small window lists the new host under "... may then also:". Nothing has changed yet. Your agent keeps running on its old version.
4. If you agree: press **Allow and update all**. If your owner policy does not allow `api.example.com`, the agent updates without it. Allow it under **Reach one named host** in **Owner policy** and **Save policy**, or allow it for this agent alone on its card.
5. If you do not agree: press **Not now**.

The panel **One file in detail** shows the same change for one file in more detail: **Adds:** and **Removes:**, each with what your owner policy would do, and the button **Update and grant (the install)**.

## I want ... change this

| I want ... | Change this |
| --- | --- |
| an agent to publish without asking me every time | **Agent rules**, **Grant a standing approval**: **Agent**, **Action** **Publish**, **Limit per calendar month (times)**, **Expires on**, **Grant**. "Publishes" cannot be lowered below "Asks you first". |
| an agent to ask me before every outside action | **Autonomy levels**: raise **Publishes** and **Sends messages outside the box** to **Always asks, with a reason**, and **Revoke** its standing approvals in **Standing approvals**. |
| an agent to ask before it writes knowledge or the workboard | **Autonomy levels**: raise **Writes company knowledge** or **Changes the workboard** to **Asks you first**. |
| to read every result before anyone else sees it | **Autonomy levels**: raise **Writes files in its own workspace** to **Waits for your check**. |
| to stop agents from reaching the internet | **Owner policy**: untick **Reach the internet addresses your company allows**, **Save policy**. Agents installed afterwards do not get it. An agent that has it keeps it until it is changed, updated or installed again. |
| to allow one more website | A website answered at install: **Change** on the agent in **Installed agents in detail** and choose the other website (one per install), then **Save and apply**. A fixed host the agent declares: **Allow for** the agent on its card, or allow it under **Reach one named host** in **Owner policy**. |
| one agent to hand work to another | The agent's card: **Allow all hand-offs for** the agent, or under **Details** the **Allow for** button of one other agent. Or **Owner policy**: **Hand work to one other installed agent** with the other agent's package name, **Allow**, **Save policy**. |
| my data never kept or trained on | **Which AI providers may see your data**: keep **Never kept, never trained on**. |
| my data to stay in Switzerland | **Which AI providers may see your data**: **Switzerland only**, and the provider PHOENIQS. See [The Swiss-only option](/admin/ai-providers-and-lanes/#the-swiss-only-option). |
| a cheaper or a stronger model | **Settings** › **Advanced** › **AI**, **Model lanes**: choose another model for the lane, **Save lanes**, **Apply to installed agents**. |
| to install agents from a new publisher | **Settings** › **Advanced** › **Agents**, **Trusted publishers**: paste the publisher's key, **Add publisher**. |

## Good starting settings for a small company

- **Data rule:** keep **Never kept, never trained on** and **Any country**. Choose **Switzerland only** only if your data must stay in Switzerland.
- **Owner policy:** a new box starts with the recommended policy. Allow more only when an agent needs it. Each agent's page lists them as "Tick it".
- **Do not allow** unless an agent you trust needs it: **Spend money up to a per-action limit (asks first)**, **Read or use a stored password or key (asks first)**, **Deploy or release (asks first)**, **Submit an on-chain transaction (asks first)**.
- **Autonomy levels:** keep the defaults. For a new agent, raise **Writes files in its own workspace** to **Waits for your check** for the first weeks, so you read every result. Go back to the floor when you trust it.
- **Standing approvals:** none at the start. Add one only for an action you approved many times.
- **Budget:** set a monthly limit you are comfortable with on **Settings** › **The AI and costs**. See [Budget](/setup/budget/).

Leave these alone unless you know why: **Model lanes** and **Fallback lane (no lane permission)** (the box fills them for your provider), **Trusted publishers** (add a key only when a publisher gives you one), and **Hand work to one other installed agent** (only when an agent's page names the other agent).

<NotYet>
You cannot set a level for one install only (a level applies to every install of the package), lower a level below its floor, make a repository action ask before it happens, or apply a changed owner policy to every installed agent at once. Workarounds: install a separate package for different levels; to approve each repository change, remove the repository permission and ask the agent to describe the change; after a policy change, press **Apply the rules** on each agent in **Installed agents in detail**.
