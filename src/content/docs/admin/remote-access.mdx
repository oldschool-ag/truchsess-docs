"One address for this box that works inside and outside the office: a person opens it, enters their e-mail, types the one-time code Cloudflare sends, and is in the portal as themselves. No VPN, no app. The local address keeps working unchanged. Off unless the admin switches it on here."

## Who can do this

- The administrator switches it on (in the office) and off, on **Administration** › **Remote access**.
- Everyone with an account uses the remote address.

## Before you start

- A remote access code from the vendor. It starts with `truchsess-remote-v1.`
- The box reaches the internet.

## Steps

### Switch on

See [Remote access setup](/setup/remote-access/#steps).

### Use the remote address (everyone)

On the remote address you never need a password. Cloudflare checks your e-mail with a one-time code, and the box lets you in when that e-mail belongs to an active account on the box.

1. Open the remote address your administrator sent you.
2. Enter your work e-mail.
3. Type the one-time code that arrives by e-mail.
4. You are in the portal as yourself. A session lasts 12 hours.

This also works for a new member who still has a temporary password: the remote address does not ask for it. The password is changed only in the office, on **https://truchsess.local/**. On the remote address, **Your account** (press your name at the bottom of the navigation) says: "On the remote address you sign in with your e-mail code; your password is changed in the office, on the local address."

### If no code arrives

- Look in your spam folder.
- Wait a few minutes before you ask for a new code. Repeated requests are slowed down.
- Ask your administrator to check that your exact e-mail address is on the remote access list. Cloudflare says a code was sent even for an address that is not allowed, so "code sent" does not prove that you are on the list.

### Let a person in (administrator)

Each person needs two things, with exactly the same e-mail address:

1. Their e-mail on the Cloudflare access list. The operator manages this list; send them the address.
2. An account on the box: **Administration** › **People and access**. See [People and access](/admin/users/).

If either is missing, or the two addresses differ in any letter, the person gets no code or sees "Your e-mail is not a member of this Truchsess. Ask your admin."

### Switch off

1. Open **Administration**, then **Remote access**, panel **Remote access**.
2. Press **Switch off**, then **Confirm switch off**.

"Remote access stops for everyone and the stored code is deleted. A new code from the operator is needed to switch it on again." You can switch off from the remote address too.

## What you see afterwards

- "State: Off.", "State: Connecting." or "State: Connected.", with the **Address**, the **Last contact**, and who switched it on or off.
- A last error, if any, for example that the box cannot reach the remote service.

## What works where

| Works on the remote address | Only in the office, on https://truchsess.local/ |
| --- | --- |
| **Chat**, **Runs**, **Approvals**, **Agents** (with your products and requests) | Signing in with a password, changing a password (also a temporary one) |
| Voice input (**Hold to talk**) | **Change AI provider** |
| Reading the Administration pages | **Switch to managed AI** with an activation code |
| Approving and refusing, standing approvals | Adding users, resetting a password, enabling a person, changing a name or e-mail |
| Installing and uninstalling agents (store and package file) | **Operator access over SSH**: SSH keys and the SSH switch |
| Owner policy, data rule, autonomy levels, model lanes | Store enrolment, trusted publishers |
| Budget: editing, top-up requests and their download | Switching remote access on |
| Adding a product, assigning and removing product access | Connections (GitHub, API keys) |
| Disabling and removing a person | Knowledge import |
| Company name, the **Voice input** setting, self-tests | Updates, backups, restore, backup downloads |
| Switching remote access off | |

On the remote address these show: "Enter this in the office, on the local address."

Voice input works on the remote address too. The recording then passes through Cloudflare like typed text, and the chat says: "On the remote address your recording passes through Cloudflare on its way to this box."

## Messages on the remote address

| Message | Meaning |
| --- | --- |
| "Your e-mail is not a member of this Truchsess. Ask your admin." | No active account with this e-mail on the box: unknown, disabled or removed. |
| "Remote access needs the e-mail code. Open the remote address again and sign in with your e-mail." | Sign in again with your e-mail. |
| "Remote access is switched off on this box. Use the local address in the office." | The administrator switched it off. |

## Your choices

| Choice | What it does | When to pick it | Can you undo it? |
| --- | --- | --- | --- |
| **Switch on** | Opens the remote address through Cloudflare. While it is on, Cloudflare can read what you see and type on the remote address. | People work outside the office. | Yes: **Switch off**. |
| **Switch off** | Closes it and deletes the code. | Not needed, or a code may have leaked. | Only with a new code from the vendor. |

The same page also holds the panel **Operator access over SSH**: the keys that let the operator reach the box over SSH, and the switch **Turn SSH on** or **Turn SSH off**. It works only in the office.
