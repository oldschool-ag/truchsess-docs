Connections are for experts. They are on **Settings** › **Advanced** › **Connections**, with the panels **GitHub**, **Company mail**, **API keys** and **Recent changes**. Advanced is the link **Advanced (for experts)** at the bottom of Settings.

"Agents never come with connections." An agent can use a connection within its permissions. It can never read or copy the secret.

## Who can do this

The administrator, in the office on **https://truchsess.local/**. Connections cannot be changed from the remote address.

## What you need

- For GitHub: you are an owner of the organisation on GitHub, so you can create GitHub Apps there.
- For an API key: the key from the service.

## GitHub

### Connect

See [Connections setup](/setup/connections/#connect-github) for the steps.

### What the GitHub App may do

The box creates one GitHub App for each of your GitHub organisations. It asks GitHub for these permissions: read metadata, write contents, write pull requests, write issues, and read checks, statuses and actions.

Each agent gets a key that is narrowed to the repositories of its own permissions. So:

- an agent reaches only the repositories it was given;
- an agent pushes only to its own branches and opens pull requests;
- no agent can merge, push to the default branch, or create tags or releases.

### When the box asks for new GitHub permissions

After an update, the card may say "GitHub has not granted ... to this box yet." and list steps on GitHub:

1. Open the App's settings on GitHub (the box shows the link). Under **Repository permissions**, set what the box names. Change nothing else. Press **Save changes**.
2. Open the App's installation (link). Press **Review request**, then **Accept new permissions**.
3. Come back to the box and press **Check again**.

### Several GitHub organizations

One GitHub App per organization. Use **Connect another GitHub organisation** to add one; each organization has its own **Disconnect**. An agent works in the repositories of one GitHub organization.

1. Open **Settings** › **Advanced** › **Connections**, panel **GitHub**. Your first organization is listed first.
2. Under the list, type the new organization's GitHub name under **GitHub organisation**. With one organization connected, the name is required.
3. Press **Connect another GitHub organisation**.
4. On GitHub's page **Create GitHub App**, leave everything as it is and press **Create GitHub App**.
5. Back on the box, press **Choose the repositories on GitHub**, pick the repositories on GitHub and install the App.
6. The new organization has its own block: "Connected: ..." with its name and the number of repositories.

What it means for the agents:

- An agent reaches only the repositories it was given, in one organization. A request for another organization's repository is refused before it leaves the box.
- An install question with repositories lists them by organization, as `organization/repository`. One answer takes repositories of one organization only: "The repositories of one answer must all be in one GitHub organization."
- To use the same agent in two organizations, add it twice, once per organization. For Bob, see [A second Bob](/admin/packages/#a-second-bob-for-a-second-product).

To disconnect one organization, press **Disconnect** in its block. The question names it: "Disconnect ...? Its stored key is removed from this appliance and the agents that work in ... stop reaching GitHub; the other organisations stay connected. You then delete the App on GitHub." Its agents then show "Needs GitHub (...) from the admin" and take no tasks. The agents of the other organizations keep working.

### Manage

All on **Settings** › **Advanced** › **Connections**, panel **GitHub**, in each organization's block:

| Button | What it does |
| --- | --- |
| **Change repositories** | Opens GitHub, where you choose which repositories the App may reach. |
| **Refresh** | Reads the list of repositories again. Press it after **Change repositories**. |
| **Disconnect** | Press **Disconnect**, then **Confirm disconnect**: "The stored key is removed from this appliance and every agent with repository permissions stops reaching GitHub." Then press **Delete the App on GitHub**. |

### Refresh a GitHub connection

Each GitHub organisation's block shows **Repositories read**, and "Checked" with the time of the last check. Since release 2026.10.25-3161da0 the blocks are on the card of each agent that uses them, under **Connections it uses**.

- **Refresh** reads the list of repositories again and updates **Repositories read** and the "Checked" time on that card at once.
- If GitHub refuses, the block keeps one line, "Refresh failed" with the time and the reason, until a **Refresh** works:
  - GitHub no longer accepts the box's App key: connect the organisation again (**Disconnect**, then connect).
  - The App is no longer installed in the organisation: press **Change repositories** and install it again.
  - GitHub refused the App a token: on GitHub, open the App's installation in the organisation and accept any pending permission request, then press **Refresh** again.
  - GitHub did not answer: try again in a few minutes.
- With several organisations, one that fails does not stop the others: they are refreshed all the same.

## Company mail

The panel **Company mail** holds Microsoft 365 and Google Workspace for the company's mail, and who connected which mailbox. "The company's mail domains are under Settings > Your company." See [Company mail](/admin/company-mail/).

Each person connects their own mailbox and calendars under **Your account**: see [Connect your company mailbox](/use/email/) and [Connect your calendars](/use/calendars/).

## API keys

The panel **API keys** shows one card for each key that an installed agent needs. "A key is attached only to the hosts the agent declared, by the box, and is never readable by the agent."

1. Press **Add key** (or **Replace** for a stored key).
2. Paste the key and press **Save**.

**Remove**, then **Confirm remove**, deletes the key: "Agents that need it refuse tasks until a new key is added."

## What "ready" means

On **Settings** › **Advanced** › **Agents**, panel **Installed agents in detail**, each agent shows:

- **Ready**: every connection the agent needs is stored.
- **Needs ... from the admin** (for example "Needs GitHub from the admin"): a connection is missing. Press **Open Connections**.
- **Needs new GitHub permissions from the admin**: see [above](#when-the-box-asks-for-new-github-permissions).

The agent's card under **Agents** shows what it needs in one line, with the button that fixes it.

An agent that is not ready refuses every task before anything starts: "This agent is not ready yet. Your admin needs to connect ... under Settings > Advanced > Connections." Nothing is charged.

## What you see afterwards

- Status words: "connected", "App created, repositories not chosen yet", "failing (the host refused the last request)", "needed", "stored, no installed agent needs it".
- **Last used** shows the last time an agent used the connection.
- **Recent changes** lists who connected, replaced or removed what. "Never a secret."
- The panel **Connections** at the top says how the secrets are protected on this computer.
- After a failed attempt to connect GitHub, the card names the App the attempt may have left on GitHub, with a link to delete it. Delete it, then press **Connect GitHub** again.

## Your choices

| Choice | What it does | When to pick it | Can you undo it? |
| --- | --- | --- | --- |
| **Connect GitHub** | Creates the box's GitHub App. | Agents that work on code. | Yes: **Disconnect**. |
| **Connect another GitHub organisation** | Creates one more GitHub App, for another organization. | A product whose code is in another organization. | Yes: **Disconnect** in its block. |
| **Advanced: use an existing GitHub App** | Uses an App made elsewhere. | Your IT asks for it. | Yes: **Disconnect**. |
| **Add key** / **Replace** | Stores an API key. | An agent needs it. | Yes: **Remove**. |
| **Remove** | Deletes the key. | The key is no longer needed or was leaked. | Add a new key. |
