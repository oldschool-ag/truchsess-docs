An [autonomy level](/start/glossary/#autonomy-level) says how much a worker may do on its own before a person looks at it.

## Who can do this

The administrator sets what workers may do. Members cannot change it.

## Before you start

Read [Approvals and checks](/use/approvals-and-checks/).

## The levels in this release

This release has one fixed set of rules. There is no setting to choose a level per action yet: it comes with the next update (see the end of this page). The rules, from "on its own" to "asks every time":

| Kind of action | What the worker does today | Where you control it |
| --- | --- | --- |
| Read and write files in its own workspace, run commands in its sandbox | On its own. | [Owner policy](/admin/packages/#owner-policy) |
| Reach the internet through the allowlist, render web pages | On its own, only to allowed hosts. | Owner policy, install questions |
| Read a repository, read test results | On its own, only its own repositories. | Owner policy, install questions |
| Push its own branches, open pull requests, comment, review, create issues | On its own, only its own repositories. It can never merge, push to the default branch, or create tags or releases. | Owner policy, install questions |
| Read and write knowledge, read and change the workboard | On its own. Every write keeps the earlier knowledge version. Every call is in the run's audit trail. | Owner policy |
| Publish, send messages outside, spend money, use credentials, deploy, chain actions | **Asks the administrator first, every time.** | [Approvals](/use/approvals-and-checks/) |

The default for every protected action is "ask every time". The administrator can change this for one worker and one action with a standing approval.

## Steps

### Let a worker do one protected action without asking

1. Open the tab **Approvals**, panel **Grant a standing approval**.
2. Choose the **Package**, the **Action**, the **Limit per calendar month** and **Expires on**.
3. Press **Grant**.

Over the limit, after the expiry, or after **Revoke**, the worker asks again.

### Make a worker do less

1. Remove the permission in **Owner policy** and press **Save policy**. This affects workers installed afterwards.
2. For an installed worker: press **Change** and skip an optional install question, or **Uninstall** it and install it again.

## What you see afterwards

- Each run card shows every decision: "approved by ...", "refused by ..." or "covered by a standing approval".
- The audit trail of each run lists its steps, each approval decision, and each knowledge or workboard call.

## Your choices

| Choice | What it does | When to pick it | Can you undo it? |
| --- | --- | --- | --- |
| Ask every time (default) | The run waits for your decision. | New workers, risky actions. | n/a |
| Standing approval | The worker does one action without asking, within a monthly limit and until a date. | A repeated action you trust. | Yes: **Revoke**. |
| Remove a permission | The worker cannot do it at all. | You never want it. | Yes: allow it again (for new installs). |

<ComingNext>
**Five autonomy levels.** The next update adds a panel **Autonomy levels** under **Administration**, **Packages**. It lists each installed worker and each kind of action with its level, shown as a colored label:

| Level | Meaning |
| --- | --- |
| Runs on its own | It runs and is recorded. |
| Tells you after | It runs; you get a notice afterwards, on the tab **Approvals**, panel **Tells you after** (**Mark all as seen**). |
| Waits for your check | The run finishes, but its result is held until you press **Accept**, or **Send back** with a note. The member who started the run sees "Waiting for the owner's check". |
| Asks you first | Approval before the action. |
| Always asks, with a reason | Approval before the action, every time, with a reason. No standing approval. |

Each kind of action starts at its default (the floor). You can raise a level for one worker, never lower it below the floor:

| Kind of action | Default | You can raise it to |
| --- | --- | --- |
| Reads its own workspace, the internet through the box's list, web pages, repositories, test results, knowledge, the workboard | Runs on its own | cannot be raised |
| Writes files in its own workspace | Runs on its own | Tells you after, Waits for your check |
| Hands work to other packages | Runs on its own | Tells you after, Waits for your check |
| Writes company knowledge, changes the workboard | Tells you after | Waits for your check, Asks you first, Always asks, with a reason |
| Comments on and reviews pull requests, creates and updates issues, pushes its own branches and opens pull requests | Tells you after | Waits for your check |
| Publishes, sends messages outside the box, chains further actions, spends money (within its limit) | Asks you first | Always asks, with a reason |
| Uses credentials, deploys | Always asks, with a reason | cannot be raised |

Standing approvals then no longer cover "Uses credentials" and "Deploys": those always ask.
