---
title: Glossary
description: The words used in Truchsess and in this manual, in plain English.
---

The words in this list are linked from the other pages. They are in alphabetical order.

## Approval

A decision by the administrator before a worker does a [protected action](#protected-action).
The worker stops and asks. The administrator presses **Approve** or **Refuse** and gives a reason.
Every decision is written to the run's audit trail with the name of the person.
See [Approvals and checks](/use/approvals-and-checks/).

## Autonomy level

How much a worker may do on its own before a person looks at it.
In this release there is one fixed rule: every protected action asks the administrator first, unless a [standing approval](#standing-approval) covers it.
A setting with several levels is being built. It is not in your box yet.
See [Autonomy levels](/admin/autonomy-levels/).

## Box

The Truchsess computer in your office. The portal calls it "the appliance".
Its address in the office is **https://myai.local/**.

## Budget

The amount of money the box may spend on AI each month.
When most of it is used, the portal shows a warning. When it is used up, new runs stop until the next period or until the budget is raised.
See [Budget](/admin/budget/).

## Check

A step where a person looks at a result before it counts.
In this release the box has no separate check step: a finished result is shown at once. The [approval](#approval) before a protected action is the only stop.
See [Approvals and checks](/use/approvals-and-checks/).

## Connection

Access to an outside service that the box holds for its workers, for example your GitHub organisation or an API key of a service.
The box keeps the secret. A worker can use a connection only within its permissions, and it can never read or copy the secret.
See [Connections](/admin/connections/).

## Data rule

The administrator's rule for which AI providers may see your data: whether a provider may keep it or train on it, and in which countries it may be processed.
Every model request follows this rule. A run that cannot meet it is stopped before any data leaves the box.
See [AI providers and lanes](/admin/ai-providers-and-lanes/).

## Function

A group of workers you buy together in the store, for example "Software delivery". The store calls it a function bundle.
You pay one monthly price per function. See [Workers](/workers/) and [Store](/admin/store/).

## Install question

A question the box asks the administrator when a worker is installed, for example "which repository should this worker review?" or "which website should it look after?".
The answer becomes part of the worker's permissions. The portal lists the questions under "This package asks you to choose:".
Some questions are optional: **Skip** means the worker does not get that permission.
See [Packages](/admin/packages/#install-questions).

## Knowledge

The documents of a product that workers may read during a task, for example a handbook or product notes.
The administrator imports them. A worker reads only the knowledge of the products it was given.
See [Knowledge](/use/knowledge/).

## Model lane

A setting that decides which AI model a worker uses. There are three lanes: **Cheap**, **Standard** and **Frontier**.
The administrator chooses one model for each lane. Each worker runs in one lane.
See [AI providers and lanes](/admin/ai-providers-and-lanes/#model-lanes).

## Owner policy

The administrator's list of permissions that any worker may receive.
A worker receives only the permissions it asks for and that this list also allows. Everything else is declined at install.
See [Packages](/admin/packages/#owner-policy).

## Package

The file that contains a worker, signed by its publisher. The portal says "package" where this manual says "worker".
A package comes from the store or as a signed file (`.truchsess-bundle.tar`).

## Product

A part of your company that work belongs to, for example one app, one website or one service.
Products decide which members see what, and which knowledge a worker may read.
See [Products and knowledge](/admin/products-and-knowledge/).

## Protected action

An action with an effect outside the box. There are six: publish, send messages outside, spend money, use credentials, deploy, and chain actions (an on-chain transaction).
A worker always asks before a protected action. See [Approval](#approval).

## Publisher

The company that built and signed a package. The box installs only packages signed by a publisher the administrator trusts.

## Run

One task given to one worker. Each message you send in **Chat** becomes one run.
A run has a state (for example "Running" or "Finished"), a cost, a result and an audit trail.
See [Follow a run](/use/follow-a-run/).

## Standing approval

A permission from the administrator for one worker to do one protected action without asking each time, up to a limit per month and until an expiry date.
Over the limit, the worker asks again. See [Approvals and checks](/use/approvals-and-checks/#standing-approvals).

## Worker

An AI helper installed on the box that does tasks for you, for example reviewing code or planning marketing.
Each installed worker has a name, permissions, a model lane and its own private workspace.
In the portal a worker is called a "package" or an "agent".

## Workboard

The box's list of work cards per product. Each card has a title, a description and a status: to do, in progress, blocked or done.
Workers with the right permission read and change cards during a task.
See [Workboard](/use/workboard/).
