This step is optional. Remote access is off until you switch it on.

With remote access, the box has a second address that works inside and outside the office. A person opens it, enters their e-mail, types the one-time code that arrives by e-mail, and is in the portal as themselves. No VPN and no app are needed. The office address keeps working.

## Who can do this

The administrator, in the office on **https://myai.local/**.

## Before you start

- A **remote access code** from the vendor (the portal calls the vendor "the operator"). It starts with `truchsess-remote-v1.`.
- Read what passes through the remote service: remote access runs through Cloudflare. While it is on, Cloudflare can read what you see and type on the remote address.

## Steps

1. Open **Administration**, sub-tab **Remote access**.
2. Read the text that begins "Remote access runs through Cloudflare."
3. Paste the code into **Remote access code (from the operator; it is entered once and never shown again)**.
4. Tick **I have read what passes through Cloudflare**.
5. Press **Switch on**.
6. Wait until the state shows "Connected" and an **Address**.
7. Send the address to your members.

## What you see afterwards

- The panel shows "State: Connected.", the **Address**, **Last contact** and who switched it on.
- On the remote address, everyone sees: "You are on the remote address. Secrets, SSH and updates can only be changed in the office, on the local address."
- Only people with an account on the box get in. Others see "Your e-mail is not a member of this Truchsess. Ask your admin."

## Your choices

| Choice | What it does | When to pick it | Can you undo it? |
| --- | --- | --- | --- |
| **Switch on** | Opens the remote address. | When people work outside the office. | Yes: **Switch off**. |
| **Switch off** | "Remote access stops for everyone and the stored code is deleted." | When you no longer need it. | Only with a new code from the vendor. |

These things work only in the office, never on the remote address: signing in with a password, changing a password, the AI provider, adding users, SSH, the store enrolment, publishers, switching remote access on, connections, knowledge import, updates and backups. The remote address shows "Enter this in the office, on the local address."

<NotYet>
A member cannot sign in with a password on the remote address, and cannot set the first password there. Members do their first sign-in in the office, then use the e-mail code outside.
</NotYet>
