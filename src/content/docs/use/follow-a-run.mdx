## Who can do this

Everyone follows their own runs in **Chat**, on the agent's card and on **Home**. The administrator also sees every run of the box in the run history.

## What you need

You have started a task. See [Start a task](/use/start-a-task/).

## Steps

### On the run card (Chat)

1. Open **Chat** and choose the agent under **Agent**.
2. Each card is one run. The card updates by itself every few seconds.
3. Read the state at the top of the card. The words are explained [below](#what-the-states-mean).
4. Click a result file (for example `result.md`) or an image to open it in the panel next to the chat. **Open raw** shows the file itself. **Close** closes the panel.

To follow your runs on a phone, and to have answers read aloud, see [Use it on your phone](/use/phone-and-voice/).

### Your recent tasks (Agents and Home)

1. Open **Agents** and click the agent's card. Its page lists your last five tasks under **Recent tasks**, each with its state. Click a task to open its run card in **Chat**.
2. **Home**, section **Recent results**, shows your last finished tasks with the agent and the time. Click one to open it.

### In the run history (administrators)

The full list of every run is for experts: **Settings** › **Advanced** › **Activity and audit trail**. **Advanced** is the link **Advanced (for experts)** at the bottom of **Settings**.

1. Open **Settings** › **Advanced** › **Activity and audit trail**, panel **Run history**.
2. Choose an agent under **Agent**, or keep "All agents".
3. Optional: choose a filter. Each filter shows the number of runs it holds:
   - **All**: every run.
   - **Needs you**: runs that wait for an approval or for the administrator's check.
   - **Active**: runs that are not done and do not wait for anyone.
   - **Finished**: runs that ended with "Finished".
   - **Failed or cancelled**: runs that failed or were cancelled.
   - **Routines**: runs that an agent started on its own schedule.
4. Optional: type in "Search tasks". The list keeps the runs whose task text or agent name contains your words. If nothing matches, you see "No run matches this filter."
5. Read the table: **Started**, **Agent**, **Task**, **State**, **Ended**, **Lane**, **Tokens**, **Cost**, **Approvals**, **Files**.
6. Press **Audit** to see every event of the run in the panel **Audit trail**: **Time**, **Event**, **Actor**, **Summary**. **Close** closes it.

### Cancel a run

1. On the run card, or in **Run history**, press **Cancel run**.
2. A reason field appears. Write why, or keep "Not needed any more."
3. Press **Confirm cancel** within 10 seconds. **Cancel** keeps the run going.

## What you see afterwards

- A finished run shows "Finished", the agent's reply, the result and its files.
- The card shows the run's [autonomy level](/admin/autonomy-levels/) as a colored label, and notices as "Told you after: ...".
- A cancelled run shows "Cancelled" with the reason.
- A failed run shows "Failed:" and the reason in the box's own words.
  When it failed without a result, "The agent's last message" shows what the agent said last, as plain text without links.
- When the agent could not open a website, the card says why in one sentence: the agent cannot read websites you name, your company rules do not allow it yet, or the website is not one the agent is set up for. An administrator sees where to change it; a member sees whom to ask. See [Let an agent read a website](/use/websites/#if-it-does-not-work).
- A task that read websites shows **Pages read** and the screenshots the agent took. A finished run offers "Download the report:" with **PDF**, **Markdown** and **HTML**. See [Let an agent read a website](/use/websites/).

### What the states mean

| State | Meaning |
| --- | --- |
| "Created, waiting for the agent" | The box has the task and is starting the agent. |
| Working | The agent is starting in its own closed workspace. |
| Running | The run is in progress. |
| Waiting for your approval | The agent asked before an action. The administrator decides. See [Approvals and checks](/use/approvals-and-checks/). |
| Waiting for your check | The run is done, but its result waits for the administrator's check. A member sees "Waiting for the owner's check" and gets the result after **Accept**. |
| Waiting for your answer | The agent asked you a question. Answer it on the card or in the message box. |
| Needs something | The task cannot go on without something, for example a connection. The card shows one line and the button that solves it. See [When an agent needs something first](/use/agent-needs-something/). |
| Finished | Done. Read the result. |
| Failed | Stopped with an error. The reason is on the card. |
| Cancelled | Someone cancelled it. |

### Hand-offs between agents

An agent that the administrator allowed to "Hand work to one other installed agent" can give part of a task to that other agent while it works, and use the answer in its own reply. The other agent works with its own permissions only, never those of the agent that asked.

- The card of a task that handed work over shows the chain of agents at the top of a block (for example Gideon → Website Owner), with the note "... handed parts of the task to these agents; the answer below is ...'s."
- Under it, one line per handed-over task: "Handed to ..." with the agent's name (a link to its card), the website it works on, the pull request it opened ("→ pull request" with the link), its state and its cost. The line "Cost with the handed-over tasks" shows the total.
- The card of a handed-over task says "Started by ...'s run", with a link back, and the website it works on for that run.
- A website agent such as Website care takes work only for its own website. An agent with a website of its own hands over work for that website only; an agent without one names the website. When Website care is installed twice for one website, the agent asks you which one should take the work: answer its question.
- If no Website care is installed for the website, the agent says so in its answer ("... is not set up for ..."). Install Website care for that website, or give the work to it yourself in a new task.
- Website changes for Website care always wait for an administrator first, on a card with one tick box per change, whatever the autonomy levels say. See [Send website changes to Website care](/use/websites/#send-website-changes-to-website-care-administrators). Other hand-offs follow the level "Hands work to other packages" (see [Autonomy levels](/admin/autonomy-levels/)).
- Handed-over tasks appear in the chat and the run history of the person who started the first task.
- Limits: at most three handed-over tasks open per task, and at most two levels deep (a handed-over task may pass work on once more). Work is never handed back to an agent that already took part. An agent that runs on a local model does not take handed-over work. When the monthly budget is used up, no handed-over task starts. In each case the agent says why in its answer.
- While two tasks wait for work they handed over, a new task can show "Created, waiting for the agent" for a while.

An agent step may take up to 10 minutes, or 30 minutes for an agent that uses a web browser. If a step takes longer, the box tries once more, then the run fails.

The cost line shows the cost, with "so far" while the run is going.
With the managed AI it is the cost the provider reported.
With your own AI key, when the provider reports no cost, "(estimated)" means the box estimated it from the provider's public price list.
"(partly estimated)" means this for some of the agent's steps.
"price unknown" means neither is known; the box never shows 0.00 instead.

## Your choices

| Choice | What it does | When to pick it | Can you undo it? |
| --- | --- | --- | --- |
| **Cancel run** | Stops the agent. Nothing is retried. | The task is wrong or no longer needed. | No. Start a new task instead. |
| **Needs you**, **Active**, **Finished**, **Failed or cancelled**, **Routines** (Run history) | Shows only the runs in that state. **All** shows every run again. | To find a run quickly. | Yes: press **All**. |
| "Search tasks" (Run history) | Shows only the runs whose task or agent name contains your words. | To find one task. | Yes: clear the field. |
| **Show self-tests** (Run history) | Also shows the box's own test runs. | Only when support asks. | Yes. |

<NotYet>
You cannot continue a finished run, reply to an agent inside a run (except to answer its question), or share a run with a colleague. Send a new task that refers to the earlier result, and share the result file another way. Members cannot see the runs of other people, and the run history and the audit trail are for the administrator only: a member asks the administrator for the audit trail of a run.
