A [function](/start/glossary/#function) groups one or more agents that you subscribe to together in the store. Each page below says what the function is for, its permissions, its install questions, its default autonomy and example tasks. The price is on the function's card in **Agents** › **Store**, and on the function's catalog page where the page links one.

Which functions your box can subscribe to is shown on the page **Agents**: an administrator presses **Store** at the top. The Store lists every function as a card, the ones you subscribed to first. Each agent there shows what it may do, one line per permission, marked "granted", "not allowed by your rules" or "you choose at install". See [Store](/admin/store/).

The installed agents are cards on the same page, in two rows: **Your agents** and **More agents on this box**. Each person has their own agents, and the box checks it before every task: a person gives tasks only to the agents in their own **Your agents**. Click a card to open its settings. An administrator chooses there **Who may use it**: **Everyone**, or **These people**. Members add an agent with its card's button **Add this agent**; when they may not add it alone, the button asks an administrator, once a day per agent. Updates show on the card ("Update available"). Each install in detail, files and the trusted publishers are in **Settings** › **Advanced** › **Agents**; **Advanced** is the link **Advanced (for experts)** at the bottom of **Settings**. See [Install and manage agents](/admin/packages/#your-agents).

## A function answers as one agent

The agents of one store function are one card, and you add, remove and allow them together. A function with a lead answers as one agent: in **Software delivery** you write your task to Bob, Bob decides which of his roles takes it, and can hand it to several in turn. You get one answer from Bob. The run shows the chain, for example "Bob → QA Reviewer → Merge Gate", with what each role did and what it cost. An administrator can still try one role with **Test this role alone** in the function's settings. See [Functions with several agents](/admin/packages/#functions-with-several-agents).

## An agent knows its limits

- Before it runs, an agent says what it still needs, for example your mailbox, a repository or a website, with one button. Nothing runs and nothing is charged until then. See [When an agent needs something first](/use/agent-needs-something/).
- An agent reaches only the websites it was given. When a task tries another one, the run card shows "Opening ... … blocked by this Truchsess's rules". Add the website for the agent if it should reach it, for example with **Change** on the install.
- "What ... may do" in the agent's settings lists everything the agent asks for, each with its state. See [What an agent may do](/admin/packages/#what-an-agent-may-do).

## Agents that work on a schedule

Some agents offer a routine: work on a schedule, so the answer is ready before you ask. Penn, for example, checks new mail during office hours. An administrator allows routines in **Settings** › **Advanced** › **Agent rules**, panel **Agents may work on a schedule**. Each person then switches a routine on for themselves, under **Works on its own** in the agent's settings. A routine runs as that person only. See [Agents that work on a schedule](/admin/packages/#agents-that-work-on-a-schedule).

## Rules every agent follows

- It works only in its own closed workspace on the box.
- It receives only the permissions it asks for that you allow: in the owner policy, or with your answer at install for one website, one repository or one product. See [Agent rules explained](/admin/agent-rules/).
- It reaches only the repositories, products and websites it was given at install.
- It never sees a stored key or password.
- It never merges on GitHub, never pushes to the default branch, and never creates tags or releases.
- It works only for the people who have it in their own agents.
- It works on a schedule only when your company allows it and a person switched its routine on for themselves.
- It asks the administrator before every protected action. The question waits on **Home**, section **Needs you**.
- Each task is a run with an audit trail, in **Settings** › **Advanced** › **Activity and audit trail**.
