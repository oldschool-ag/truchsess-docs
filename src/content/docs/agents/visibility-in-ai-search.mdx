Store function id: `visibility-in-ai-search`. Price and full description: [Visibility in AI search in the store catalog](https://faivr.ai/catalog/visibility-in-ai-search).

## What it is for

One agent that checks how one website is found, described and recommended by search engines and AI answer tools, and writes fixes ready to hand over.

## Who can do this

- The administrator subscribes, answers the install questions and allows the permissions.
- Administrators, and the people the agent's card allows under **Who may use it**, give the agents tasks in **Chat**.

## What you need

- The box is connected to the store and the function is subscribed. See [Store](/admin/store/).
- In **Settings** › **Advanced** › **Agent rules**, panel **Owner policy**, allow the permissions marked "Tick it" or with a value below. A new box already allows several of them. Permissions with an install question are allowed by your answer. See [Owner policy](/admin/packages/#owner-policy). **Advanced** is the link **Advanced (for experts)** at the bottom of **Settings**.
- Answer the website question at install. The agent reaches exactly that host and a web search page.

Facts on this page come from the packages' published definitions (checked on 8 October 2026). Your box shows the same facts on the function's card in **Agents** › **Store**, under "What it may do".

## The agent

### Gideon

Package id `faivr.agent.ai-visibility`, version 1.0.0.

Checks and improves how one website is found, described, cited and recommended by search engines and AI answer tools. Each finding says how strong its evidence is, and each fix is ready to hand over.

**Permissions in plain words**

| Permission | Install question | In **Owner policy** |
| --- | --- | --- |
| Read its own files | None | Tick it |
| Create and change its own files | None | Tick it |
| Use its own tools, closed off from the rest of the box | None | Tick it |
| Reach the internet addresses your company allows | None | Tick it |
| Open web pages and take screenshots with its own browser (needs its own tools and the allowed addresses) | None | Tick it |
| Reach one named host | *Which website should it audit for AI search visibility?* | Allowed by your answer |
| Reach one named host: `html.duckduckgo.com` (a web search page) | None | **Reach one named host**: enter `html.duckduckgo.com` and press **Allow** |
| Read one product's knowledge | *Which product's knowledge may it read for context?* (optional) | Allowed by your answer |
| Use one level of AI: **Standard** | None | **Use one level of AI (cheap, standard or the strongest)**: choose `standard` and press **Allow** |

**Install questions**

- *Which website should it audit for AI search visibility?* Required. You choose one website address, for example `www.example.com`.
- *Which product's knowledge may it read for context?* Optional: **Skip (the permission is declined)** is offered. You choose a product of the box.

**Hand-offs:** during a task it may hand part of the work to these agents, if they are installed: Website Owner, Ivy. The other agent works with its own permissions only. In **Owner policy**, allow **Hand work to one other installed agent** with the package id of each one, for example `faivr.agent.website-owner`. See [Hand-offs between agents](/use/follow-a-run/#hand-offs-between-agents).

**Improvements for your website:** when Gideon finds improvements for your website and Website care is installed for the same website, it hands them to Website care. They always wait for an administrator first, on a card with one tick box per change: see [Send website changes to Website care](/use/websites/#send-website-changes-to-website-care-administrators). The pull request then appears on Gideon's run card. Gideon never hands work over for another website.

**Default autonomy levels**

Shown and changed in **Settings** › **Advanced** › **Agent rules**, panel **Autonomy levels**. It has no protected actions, so it never asks for an approval unless you raise a level to "Asks you first".

| Kind of action | Default level | You can raise it to |
| --- | --- | --- |
| Reads its own workspace | Runs on its own | cannot be raised (Fixed) |
| Writes files in its own workspace | Runs on its own | Tells you after, Waits for your check |
| Reaches the internet through the box's list | Runs on its own | cannot be raised (Fixed) |
| Renders web pages in its sandbox | Runs on its own | cannot be raised (Fixed) |
| Reads company knowledge | Runs on its own | cannot be raised (Fixed) |
| Hands work to other packages | Runs on its own | Tells you after, Waits for your check, Asks you first, Always asks, with a reason |

## What every agent can never do

- Work outside its own closed workspace on the box.
- Reach hosts, repositories or products it was not given.
- Merge on GitHub, push to the default branch, or create tags or releases.
- Read a stored key or password.

## One website per install

Gideon checks exactly the website you entered at install. The box blocks every other website for it. Give it tasks about that website only.

To check another website, change the answer: **Settings** › **Advanced** › **Agents**, panel **Installed agents in detail**, Gideon's install, **Change**, then enter the other website and press **Save and apply**. One install checks one website at a time.

If you ask Gideon about another website, the box does not let it open that website. The website is fine. The run card says why in one sentence, for example "... may reach only the websites it is set up for. This is a rule of this box, not a fault of the websites."
When the task has ended, one line under the answer names an agent on your box that can read the websites you name, or a Store function that has one, with one button. See [When an agent needs something first](/use/agent-needs-something/).

<Aside type="note" title='A version that reads the websites you name'>
When the version of Gideon on your box can read the websites a person names, its list of what it may do has the line "Read the websites a person names in a task (only those, only for that task)". It then reads any website you name in a task, for that task only, and asks for no fixed website at install. You list your own websites under **Your websites** instead. See [Let an agent read a website](/use/websites/).
</Aside>

## Example tasks

Write these in **Chat** after choosing the agent. Change the details to your company.

1. *Audit our website for AI search visibility and list the findings with how strong the evidence is.*
2. *Search for our company name and tell us how the results describe us.*
3. *Write the three most important fixes for our home page as ready-to-use text.*
